# 01 · EDSR ×3 — 흐린 위성사진을 3배 선명하게

Sentinel-2 위성이 찍은 10 m짜리 사진을 IKONOS급 3.33 m짜리처럼 만드는 모델이다.
가로세로 각각 3배로 키우기 때문에 **×3 초해상화**라고 부른다.

[EDSR](https://github.com/sanghyun-son/EDSR-PyTorch) 이라는 공개 모델을 그대로 쓰고,
위성사진을 읽고 쓰는 부분만 새로 붙였다. 파라미터 150만 개로 요즘 기준에는 작은 편이라
Colab 무료 GPU에서도 몇 분이면 학습된다.

| | |
|---|---|
| 넣는 것 | 10 m 위성사진 (RGB 3색) |
| 나오는 것 | 3.3333 m 사진. **위치 정보가 그대로 붙어 있어** QGIS에서 원본 위에 겹쳐볼 수 있다 |
| 노트북 | [`../../notebooks/01_edsr_x3.ipynb`](../../notebooks/01_edsr_x3.ipynb) |

원본 프로젝트의 자세한 실험 기록은 `code/README_S2SR.md` 에 있다.

## 연습문제와 실전시험이 다르다

이 실습에서 가장 중요한 부분이다.

- **연습문제(`training/`)** — 선명한 정답 사진을 일부러 3배 줄여서 흐리게 만든 것.
  정답에서 만들어냈으니 색과 밝기가 정확히 맞는다.
- **실전시험(`validation/`)** — 진짜 Sentinel-2가 찍은 흐린 사진. 찍은 날도 위성도 다르니
  색이 다르고 그림자 위치도 다르다.

그래서 실전시험 점수에는 "선명하게 만드는 실력"만이 아니라 **"사진끼리 원래 안 맞는 정도"**
까지 섞여 들어간다. 점수가 잘 안 오르는 게 정상이다.

실전시험 사진은 배울 때 한 번도 안 본 지역에서 골랐다. 원래 12곳이었는데 두 곳
(`AOI_Athens_2`, `AOI_Athens_10`)은 찍은 시기가 너무 달라 **아예 다른 풍경**이라 뺐다.

## 연습문제를 고른 기준

후보 804장 중 **683장**만 쓸 만하다고 보고 거기서 40장을 골랐다. 뺀 이유는 세 가지다.

**1. Athens 사진 100장 전체 — 너무 밝게 찍혔다**

하얗게 타버린(값이 255로 잘린) 부분이 평균 10.97%, 100장 중 90장이 5%를 넘었다.
하얗게 탄 부분은 원래 밝기가 지워진 상태라 되살릴 방법이 없다.

더 큰 문제는 정답 사진에는 하얀 부분이 11%인데 흐린 사진에는 5%뿐이라는 것이다.
그러면 모델이 **"밝은 곳은 하얗게 만들어라"** 를 배워버린다. 잘못된 걸 가르치는 셈이다.
다른 도시들은 0.38~2.93%로 정상이라, Athens만 통째로 뺐다.

**2. 하얗게 탄 부분이 5% 넘는 사진 17장** — 같은 이유다.

**3. 검은 구멍이 안 맞는 사진 4장** — 전부 `AOI_Munich_15` 계열이다.
흐린 사진에만 촬영 범위 밖의 검은 영역이 2.6~4.2%p 더 있었다. 사진을 만드는 과정의 실수다.

거른 결과 하얗게 탄 비율이 **평균 2.31% → 0.63%** 로 내려갔다.

### 이건 문제가 아니다

정답 사진과 연습용 흐린 사진 사이에 **색 차이는 없다.** 정답에서 줄여 만들었으니 당연한데,
실제로 재봐도 밝기 차이가 0.41 DN(255단계 중 0.41)에 불과하다.

픽셀 차이가 커 보이는 사진이 있긴 한데 **그건 불량이 아니라 디테일이 많은 사진이다.**
복잡한 사진일수록 크게 줄이면 잃는 게 많으니 차이가 커지는 게 당연하다
(차이와 복잡도의 상관관계가 +0.63). 이런 사진은 모델이 배워야 할 가장 좋은 자료라
빼면 손해다.

직접 확인해보려면 `python tools/check_pairs.py` 를 실행하면 된다.

## 미리 학습해둔 파일

밑바닥부터 배우면 오래 걸려서, 어느 정도 배워둔 상태에서 이어서 학습한다.

| 파일 | 무엇으로 배웠나 | 언제 쓰나 |
|---|---|---|
| `edsr_ikonos_x3_best.pt` | 캐나다 산불 지역 → 도시 39곳, 30회 반복 | **이어서 학습할 때 출발점** |
| `edsr_ikonosfull_x3_latest.pt` | 위 + 도시 전체 사진 10회 추가 | 결과가 가장 좋다. 인천 사진 시연용 |

두 번째 파일은 이름이 `latest`인 게 맞다. 그 학습은 시험을 안 보고 진행해서
`best`(가장 점수 높았던 시점)라는 게 의미가 없다.

## 학습시키기

설정은 전부 환경변수로 넘긴다.

```bash
GPU=0 DATA=COLAB DIR_DATA=/content/colab/dataset \
EPOCHS=11 DECAY=5-8 LR=1e-4 TEST_EVERY=100 PRINT_EVERY=20 N_THREADS=2 \
SAVE=edsr_colab_x3 SAVE_RESULTS=0 RESET=1 \
PRETRAIN=/content/colab/models/01_edsr_x3/checkpoints/edsr_ikonos_x3_best.pt \
bash code/run_train.sh
```

| 설정 | 뜻 |
|---|---|
| `DIR_DATA` | 사진이 있는 폴더 (`training/`·`validation/`의 부모) |
| `EPOCHS` | 문제집을 몇 번 반복할지. **11을 넣으면 실제로는 10번 돈다** |
| `TEST_EVERY` | 한 번 돌 때 문제를 몇 개 풀지 (실제 개수 = 16 × 이 값) |
| `PRINT_EVERY` | 진행 상황을 몇 번마다 찍을지. `TEST_EVERY`보다 크면 기록이 하나도 안 남는다 |
| `LR` | 한 번에 얼마나 크게 고쳐잡을지 |
| `RESET=0` | 연결이 끊겼을 때 이어서 학습 |

## 써보기

```bash
# 사진에 적용 — 폴더를 주면 안의 .tif 전부 처리한다
python code/infer.py --weight <학습된 파일> --input <폴더 또는 .tif> --output results/

# 점수 매기기 — 정답 사진이 있어야 한다
python code/evaluate.py --weight <학습된 파일> --src <사진 폴더> --lr_name LR --radio_match
```

`evaluate.py` 는 `{지역이름}/{HR,LR}.tif` 형태의 **원본 위성사진 폴더**를 받는다.
이 번들의 `validation/` 은 잘라낸 조각(PNG)이라 그대로는 못 쓴다.

## 성능

10번 반복 학습 기준 (RTX 3090에서 40초, Colab T4는 3~5분):

| | 결과 |
|---|---|
| 연습문제 점수 | 15.79 → 14.99 (낮을수록 좋음, 계속 내려감) |
| 실전시험 점수 | **16.05 dB 가 최고, 1회차 이후 정체** |
| 인천 사진 선명도 | 그냥 확대 8.82 → 이 모델 **12.24** (1.4배 또렷) |

**연습문제 점수는 계속 좋아지는데 실전시험이 멈추는 게 정상이다.**
연습문제는 정답에서 만들어서 규칙이 일정하지만, 실전은 다른 날 다른 위성이 찍은 사진이라
익힌 규칙이 그대로 안 통한다. 더 올리려면 연습문제를 일부러 실전처럼(색을 틀고 노이즈를 섞어)
만들어야 한다.

## 자주 걸리는 함정

**1. `--chop` 옵션을 켜면 에러가 난다.** 원본 코드의 버그다. 큰 사진은 `infer.py` 가
조각내서 처리하니 그냥 쓰면 된다.

**2. 사진을 바꿔 넣었는데 예전 게 계속 나온다.** `dataset/bin/` 폴더를 지우세요.
속도를 위해 미리 변환해 저장해두는데, 파일 이름이 같으면 예전 것을 재사용한다.

**3. 색 보정값이 고정되어 있다** (`code/src/model/common.py:15`). 일반 사진용 평균값이
박혀 있는데, 넣고 뺄 때 같은 값을 쓰니 학습에는 지장이 없다. 다만 색 개수를 3에서 바꾸면
반드시 고쳐야 한다.
