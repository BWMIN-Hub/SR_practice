# 02 · SRGAN ×3

[leftthomas/SRGAN](https://github.com/leftthomas/SRGAN) 을 우리 위성 데이터셋으로 학습한 것.
**모델 구조와 손실은 업스트림 그대로**이고, 데이터셋만 바꿨다.

| | |
|---|---|
| 넣는 것 | 10 m 위성사진 (RGB 3색) |
| 나오는 것 | 3.3333 m 사진 |
| 학습 | IKONOS 804쌍, 100 epoch, batch 32, crop 96 |
| 노트북 | [`../../notebooks/02_srgan_x3.ipynb`](../../notebooks/02_srgan_x3.ipynb) |

## 배율 ×3 을 위해 고친 곳

업스트림 Generator 는 ×2 업샘플 블록을 `log2(scale)` 번 쌓는다. 그래서 3 을 주면
블록이 1개만 생겨 조용히 ×2 출력이 나온다(32px → 96px 이어야 하는데 64px).

2의 거듭제곱이 아니면 `PixelShuffle(scale)` 블록 하나를 쓰도록 바꿨다.
×2/×4/×8 경로는 레이어·파라미터가 이전과 동일하고 기존 체크포인트도 그대로 로드된다.

## 성능 (검증 10패치, 가장자리 4px 제외)

| | PSNR | SSIM |
|---|---|---|
| Bicubic | 18.15 | 0.4805 |
| **SRGAN x3 (epoch 70)** | **18.30** | **0.5187** |

PSNR 은 +0.15 dB 로 작지만 SSIM 이 +0.038 로 뚜렷하다. GAN 계열이 화소 오차보다
구조를 살리는 쪽으로 학습되기 때문이다.

## 판별자 붕괴

`statistics/x2_train_results.csv`, `x3_train_results.csv` 에 epoch 별 기록이 있다.
배율만 다른 두 학습에서 **정반대 방향으로** 붕괴했다.

| | 붕괴 시점 | `D(x)` | `D(G(z))` | 판정 |
|---|---|---|---|---|
| x2 | epoch 5 | 0.0000 | 0.0000 | 전부 "가짜" |
| x3 | epoch 38 | 1.0000 | 1.0000 | 전부 "진짜" |

`Loss_D = 1 - D(x) + D(G(z))` 는 두 경우 모두 정확히 **1.0** 이라, 손실 그래프만으로는
구분되지 않는다. `adversarial` 항이 상수가 되어 기울기가 0 이 되고, 그 뒤로는
사실상 MSE + VGG 손실만으로 학습된다.

원인은 손실이 sigmoid 출력에 대해 **선형**이라는 데 있다. 로짓에 대한 기울기가
`s(1-s)` 로 스케일되므로 로짓이 포화 구간에 들어가면 복구 경로가 없다.
표준 GAN 의 `log D` 형태였다면 틀릴수록 기울기가 커져 이런 고착이 덜하다.
